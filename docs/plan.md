# Plan: Fast multi-user Linux RDP terminal server (broker + native back-ends)

## Context
Goal: a Windows-RDS-like **multi-user** Linux terminal server. It should feel fast (GPU where
possible), authenticate against the existing Kerberos realm (Samba AD / MIT) with MFA
(privacyIDEA, Keycloak, YubiKeys, smartcard/FIDO2 where feasible), and offer all common
desktops, **X11 and Wayland**. We integrate existing software and add a small amount of glue.
We do not write a new RDP stack. The work is an Ansible-driven deployment plus one
custom component, a session broker. It lives in `/home/sandbox/git/fast-rdp-server`, which is
empty today. GPU targets: NVIDIA, Intel/AMD and CPU-only VMs (Vulkan included). Primary OS:
Debian 13 / Ubuntu 26.04. RHEL 10 is secondary.

### Facts as of Oct 2026 that shape the design
- **xrdp 0.10.6.1** (Jul 2026): GFX + H.264 (x264/OpenH264, **software only**), and the daemon runs
  unprivileged. Supports "Xvnc over UDS" sessions. **There is no NLA in any release**; PR #3868
  (GSSAPI NLA) has been open and unreviewed since 2026-09-05. xorgxrdp-glamor gives GPU *rendering*.
- **GNOME 50 / Plasma 6.8 are Wayland-only**, so xorgxrdp can't host them.
  - GNOME: **gnome-remote-desktop** supports headless multi-user logins via GDM, Kerberos
    keytab, NLA, and H.264 hardware encoding (VA-API/NVENC).
  - KDE: **KRdp** (FreeRDP + PipeWire, VA-API H.264) officially only shares an existing session.
    Headless use means pairing it with `kwin_wayland --virtual`, which is unofficial → must be validated.
  - wlroots (Sway, labwc, Hyprland): no RDP back-end; **wayvnc** is the only exporter.
- **FreeRDP 3**: xfreerdp3 is the reference client, and the library underneath g-r-d, KRdp and Weston.
  **`freerdp-proxy3`** terminates NLA (Kerberos/NTLM), has a module API, and routes to targets.
- ogon (dormant since ~2019) is the architectural model: a broker in front of per-user sessions.
  We rebuild that model from maintained parts.

## Architecture
```
client (mstsc / xfreerdp3 / Remmina / Guacamole)
   │ RDP + NLA (Kerberos SSO or password) ─ via NetBird VPN / RD Gateway
   ▼
freerdp-proxy3  +  broker module (custom)          ← single entry, TLS cert from internal CA
   │  1. NLA auth (GSSAPI keytab / PAM fallback)
   │  2. MFA step (privacyIDEA)
   │  3. ask fastrdp-brokerd: "session for user X, desktop D"
   ▼
fastrdp-brokerd (root, systemd)  → starts/reuses per-user session, returns local target
   ├─ X11 desktops  → xrdp + xorgxrdp-glamor   (XFCE, MATE, Cinnamon, LXQt, Budgie-X11, i3…)
   ├─ GNOME 50+     → gnome-remote-desktop system daemon (GDM headless)
   ├─ Plasma 6.8+   → kwin_wayland --virtual + krdpserver (per-user port, loopback only)
   └─ wlroots       → compositor headless + wayvnc → xrdp VNC-over-UDS (lower perf; later phase)
```
Back-ends listen only on loopback/UDS. Only the proxy is exposed.

### Session broker (the custom component)
- **Proxy module** (C, FreeRDP proxy module API): after authentication it calls the broker over a
  Unix socket and rewrites the target. It injects the credentials or ticket that the back-end needs.
- **brokerd** (Python or Rust, small): maps user → desktop (choice from the AD group, from
  `~/.config/fastrdp/desktop`, or from a client hint), then starts the session as a
  systemd `--user` unit with `loginctl enable-linger` semantics. It allocates ports, reconnects
  to existing sessions, applies limits (cgroups: CPU/mem/GPU) and exports metrics.
- Credentials to back-ends: xrdp gets username/password over loopback TLS (or a short-lived
  one-time token checked by a tiny PAM module, `pam_fastrdp_token`, so the password never
  travels twice). KRdp sessions get per-session random credentials generated by the broker.
  g-r-d gets Kerberos/system creds (to be validated).

### Auth design
- Hosts join Samba AD / MIT via **SSSD**. The proxy uses the host keytab for **Kerberos NLA SSO**.
  The session gets a TGT (delegated credentials, or `pam_sss` at password login, KCM ccache)
  for SMB homes etc.
- **MFA = privacyIDEA as the single token backend** (TOTP/HOTP, **YubiKey OTP**, push). It is
  enforced in the broker module after NLA. Clients without an interactive channel fall back to a
  PAM stack (`pam_sss` + privacyIDEA PAM) at the xrdp login dialog. Push tokens work without a prompt.
- **Keycloak** uses the privacyIDEA provider, so the same tokens work for web logins. FIDO2/WebAuthn
  is available only on the web path (Guacamole + Keycloak OIDC → broker token).
- **Smartcard/PIV pre-logon**: not supported by freerdp-proxy/xrdp → documented as a gap. Watch
  FreeRDP/xrdp for smartcard CredSSP support.

### GPU / performance design
- Wayland back-ends: render on the GPU via the compositor (Mesa or NVIDIA GBM). Encode via
  **VA-API/NVENC** (g-r-d) or VA-API (KRdp). Vulkan works natively.
- X11 back-end: xorgxrdp-glamor (Intel/AMD). On NVIDIA, glamor is tested; VirtualGL 3 (EGL) is
  the fallback for GL/Vulkan apps. H.264 AVC444 via x264, tuned in `xrdp.ini [x264]`.
- VMs: llvmpipe plus software H.264, with documented per-user CPU sizing.
- Optional later: VA-API/NVENC encoder for xrdp (`xrdp_encoder*.c` already plugs in x264/openh264),
  as an upstream-contribution candidate.

## Phases
1. **Lab MVP (X11)**: xrdp + XFCE, SSSD/Kerberos, x264 GFX, TLS, accessed directly.
2. **Proxy + broker**: freerdp-proxy3 with Kerberos NLA, broker module, brokerd routing to xrdp;
   token handoff; privacyIDEA MFA incl. YubiKey.
3. **Wayland back-ends**: GNOME via g-r-d headless; Plasma via kwin --virtual + KRdp
   (spike first and decide whether it is viable); desktop selection.
4. **GPU hosts**: Intel/AMD and NVIDIA hosts; validate HW encode and Vulkan per back-end; perf tuning.
5. **Extras**: Guacamole + Keycloak web path, wlroots/wayvnc, xrdp HW encoder, upstream fixes.

## Verification
- Per desktop: `xfreerdp3 /v:proxy /sec:nla /u:user@REALM /gfx:avc444 /network:auto` (after `kinit`
  → no password prompt), plus mstsc and Remmina. Check that disconnecting and reconnecting
  returns the same session and that `klist` in the session shows a TGT.
- MFA: a wrong or replayed OTP is denied; YubiKey OTP and push both work; lockout policy is applied.
- GPU: `glxinfo -B` and `vulkaninfo --summary` in the session show the hardware device;
  `nvidia-smi` / `intel_gpu_top` show the encoder engine busy in Wayland sessions.
- Perf: scripted video and scroll workload; record fps, RTT, bandwidth and CPU per session
  (target ≥30 fps 1080p, <50 ms added on LAN); N-user soak test.
- Security: `testssl.sh` on the proxy; back-ends not reachable externally; services unprivileged
  where possible.

## Risks / spikes to resolve early
- **KRdp headless** with `kwin_wayland --virtual` (unofficial). If it fails, Plasma 6.8+ waits for
  Plasma Login Manager. Plasma X11 on an LTS distro is the stopgap.
- **g-r-d behind a proxy**: GDM handover with credentials passed through the proxy, with no second prompt.
- freerdp-proxy3: can the module run an interactive MFA step (it may need a greeter); otherwise
  use push/appended-OTP.
- glamor stability on the NVIDIA proprietary driver.

## Implementation status (2026-10-19)

Phases 1–3 are implemented in this repository. They are tested in a sandbox but not
yet deployed to a lab host; see the status table in [README.md](../README.md) and the
validation list in [desktop-matrix.md](desktop-matrix.md).

Changes from the plan while implementing:
- **gnome back-end:** per-user g-r-d *headless* mode inside GDM 50's
  `gnome-headless-session@USER`, not the system remote-login daemon. This avoids the
  second GDM login prompt.
- **xrdp handoff:** xrdp accepts only one-time broker tokens (`pam_fastrdp_token`).
  The real password, when known, is handed on so the session still gets a TGT.
- **Loopback back-ends:** protected by an nftables `skuid` rule plus a listener-uid
  check instead of certificate pinning.
