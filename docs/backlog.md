Not planned (evaluated):
- **K7: storing the TGT that FreeRDP clients forward with `/remoteGuard`** (formerly
  backlog K7). FreeRDP sends the TGT with its session key unencrypted, contrary to
  MS-CSSP; keeping it would be unconstrained delegation: root on the host could use it
  for any service until it expires, also after the user disconnected, and users who
  choose `/remoteGuard` expect that no credentials are handed over. Windows Remote
  Credential Guard avoids exactly this by keeping the TGT key on the client
  ([windows-clients.md](windows-clients.md) §3.12). Alternatives that remain: a typed
  password (the session gets its own TGT) and gssproxy S4U for NFS/SMB (constrained).
- **Kerberos delegation inside NLA** (`GSS_C_DELEG_FLAG`, forwarded TGT in the
  AP-REQ): unconstrained delegation, needs WinPR patches on both sides, and mstsc
  does not request it ([nfs-kerberos-homes.md](nfs-kerberos-homes.md) Q5b).
- **Full Remote Credential Guard for mstsc** (server-side MS-RDPEAR, a Kerberos client
  whose TGT key stays on the client): about 80–150 person-days, no open-source
  implementation to build on, and MIT krb5/KCM cannot use remote-held keys. Revisit
  only if a Windows lab shows cleartext service-ticket keys from mstsc or FreeRDP gains
  a server-side RDPEAR.
