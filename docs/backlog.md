## Host safety in RDP sessions

| # | Item | Benefit | Effort / risk |
|---|---|---|---|
| H1 | **Prevent shutdown, reboot, suspend and hibernate from RDP sessions.** **Status: implemented, host validation pending.** Analysis (systemd 257/259 logind, polkit, xrdp 0.10.6.1, GDM, pam_systemd sources): no fastrdp session has a seat (xrdp `PAM_TTY=:N`, GNOME a GDM remote display, Plasma no `TTYPath`), so polkit applies `allow_any` = `auth_admin_keep`: users see the power entries and an admin's password shuts down the shared host; only console sessions get `allow_active = yes`. Fixed: the base role installs `/etc/polkit-1/rules.d/40-fastrdp-power.rules` (`fastrdp_block_power_actions: true`): `no` for the 15 logind power actions (incl. `-multiple-sessions`/`-ignore-inhibit`) and `set-reboot-*`; members of `fastrdp_power_admin_groups` (`[sudo]`) still authenticate as admins; root unaffected; console sessions keep the upstream defaults only with `fastrdp_power_allow_local_console`. GNOME, Plasma and MATE hide the entries, XFCE greys them out (source-verified), `systemctl poweroff` is refused. Rule evaluated in node in `make test-ansible`; diagnostic `tests/smoke/check-power-actions.sh`. Open: on a host, `sudo tests/smoke/check-power-actions.sh USER ADMIN` per desktop and a look at the menus | One user cannot shut down or reboot the shared host for everyone | host validation |

Not planned (evaluated):
- **Kerberos delegation inside NLA** (`GSS_C_DELEG_FLAG`, forwarded TGT in the
  AP-REQ): unconstrained delegation, needs WinPR patches on both sides, and mstsc
  does not request it ([nfs-kerberos-homes.md](nfs-kerberos-homes.md) Q5b).
- **Full Remote Credential Guard for mstsc** (server-side MS-RDPEAR, a Kerberos client
  whose TGT key stays on the client): about 80–150 person-days, no open-source
  implementation to build on, and MIT krb5/KCM cannot use remote-held keys. Revisit
  only if a Windows lab shows cleartext service-ticket keys from mstsc or FreeRDP gains
  a server-side RDPEAR.
